## Procedural Label Blinding and Outside Lookup

This package uses **procedural label blinding**. The repository is public, and
exact candidate texts and hashes are publicly discoverable. Prior familiarity,
text comparison, repository search, or outside lookup could identify an
Assigned Candidate. The supplied packet reduces version-label, recency, and
declared-development cues; it does not guarantee ignorance.

Before the applicable responses freeze, reviewer-facing materials use a Review
ID, an Assignment ID or opaque Packet ID, neutral candidate labels and alias
filenames, neutral scenario labels and alias filenames, a packet version, and
an opaque packet-instance commitment. The administrator separately verifies
the exact canonical source bytes and keeps canonical identities, paths,
hashes, and label mappings outside reviewer-facing materials while the mapping
is withheld.

The packet-instance commitment is not a candidate hash and cannot by itself
identify the candidate. It may later help detect post-hoc remapping when an
authorized mapping record and nonce are revealed. It does not prove fair
randomization, prove source claims true, guarantee reviewer ignorance, or
provide moral authority. It is not a blockchain.

Until the applicable candidate-specific responses freeze, please do not:

- Hash candidate or scenario text and compare the result with public values.
- Search exact phrases from candidate or scenario text.
- Search canonical-looking scenario identifiers.
- Browse the public repository to infer a label mapping.

If you already had prior exposure or perform any of these actions:

- Continue only if you are comfortable doing so.
- Disclose exactly what was done.
- Record when it occurred.
- Record what was learned or inferred.
- Identify which response sections were completed before the exposure.
- Do not represent the review as procedurally label-blinded if that
  description is no longer accurate.
- Preserve the timing of the exposure so the method can be classified
  accurately.

Exposure does not automatically invalidate a response, but it changes the
response's method classification. Any actual per-reviewer mapping must remain
outside the public repository until the applicable candidate-specific and
comparative responses are frozen. No actual mapping, nonce, commitment,
packet, assignment, or response exists in this preparation package.

## Review Principles

Apply all of the following:

- Evaluate exact text, not an improved paraphrase.
- Give the strongest reasonable good-faith interpretation.
- Give the strongest plausible hostile interpretation.
- State assumptions and limitations explicitly.
- Use candidate-specific evidence and scenario-specific conclusions.
- Preserve material dissent and competing interpretations.
- Do not calculate an aggregate numeric score.
- Do not count reviews or outcomes as votes.
- Do not use majority reasoning.
- Do not issue a candidate-wide moral verdict.
- Do not claim to represent a modeled mind, field, community, or population.
- Distinguish kernel text from definitions, commentary, profiles, choice
  mechanisms, evidence, and governance.
- Criticize the evaluation framework itself where warranted.

## No Winner Request

- You are not asked which candidate "wins."
- You are not asked to rank candidates.
- If you volunteer a preference, label it clearly as unsolicited. It does not
  become the project's preference.
